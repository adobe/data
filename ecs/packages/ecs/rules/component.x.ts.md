- A key is a top-level `Symbol()` with no description, its traits declared beside it: `declare module "@adobe/ecs" { interface Components { [title]: { type: string } } }`.
- An entity reference is a component of its own, `type: Entity` with `reference: "owner"` or `"weak"`, never a field of a struct. A DOM object is `thread: "main"`.
- A derived component, `derived: true`, is defined in its own file by `Component.derive(key, { from, not })`: it's on exactly the entities some derivation of it matches, and nothing else adds or removes it.
- Shape components by how systems use their fields. A component is one array per archetype, each row's fields side by side; separate components are separate arrays. A system loads every byte of each component it reads, and kernels run four rows a vector where each field meets the same operation or a component is one value; fields combined with each other are transposed into lanes first, which costs about 2×.
  - One tuple or struct for fields every system treats alike, such as a vector or color moved by `position + velocity * dt`: a tight `Vec2`, `Vec3` or `Vec4` runs at memory speed.
  - Separate scalar components for fields systems compare or combine with each other (`hp` against `maxhp`, a status), or that only some systems use: health as three components ran 0.35 ns a row against 0.61 as one struct, and reading one `I32` of a 40-byte struct 0.42 against 0.17 as its own component.
  - Separate components for fields written at different times: `changed`, stamps and persistence track whole components, so writing one field marks the rest changed.
  - A value of each row that every field of a vector uses, such as a mass or scale, as its own scalar component, which a kernel spreads across the vector's lanes.
- Use the narrowest type that holds the value: `F32` unless the precision is needed, `I32` or `U32` for integers. Kernels compute at storage precision, so `F32` runs four lanes a vector and `number`, an f64, two, moving twice the bytes: integrating a vec3 took 0.27 ns a row in `F32` and 0.52 in `number`. Keep `F32` and `number` fields in separate components; a kernel mixing them computes the `number` ones a row at a time.
- Use a padded layout, `storage` or `vertex`, only for components the GPU reads: a vec3 padded to 16 bytes moves a third more.
