# data-ecs performance

Generated by `pnpm perf:report` from `history/`; don't edit it by hand.

- `pnpm perf [filter]` runs the node benchmarks, bundled as in production, and compares each with this machine's last record. `pnpm perf:browser` runs the chromium ones: main thread, workers and GPU.
- Add `--record` to append the results to `history/<machine>.jsonl` and regenerate this file. Record on an idle machine, and commit the record with the change it measures.
- **ns per N** is the fastest run's time divided by N. **Best** is the time to move the fewest bytes an ideal implementation must, in this ECS's storage model, at the fastest copy bandwidth the run measured, with data in the caches; **× best** is how far from it the run is, and **Room** the milliseconds between them. **Change** compares with the previous record on the same machine; beyond ±10% it says slower or faster.

## Benchmarks

### create

Spawning entities of six components, two of them tags, over four archetypes, through a main-thread system and the sync point that applies them: loading a level, a burst of particles.

- **N:** 1M spawns; usually 100–100K.
- **Best:** 48 bytes per N at the copy bandwidth of one thread, the fastest it measured. Each entity writes its 32 bytes of values, its 8-byte entity and its 8-byte location.

### create flat

The same spawns with eight scalar components each, values passed inline.

- **N:** 1M spawns; usually 100–100K.
- **Best:** 48 bytes per N at the copy bandwidth of one thread, the fastest it measured. Each entity writes its 32 bytes of values, its 8-byte entity and its 8-byte location.

### create flat dynamic

The same spawns from value objects built first, as spawns from data or from another system's results are.

- **N:** 1M spawns; usually 100–100K.
- **Best:** 48 bytes per N at the copy bandwidth of one thread, the fastest it measured. Each entity writes its 32 bytes of values, its 8-byte entity and its 8-byte location.

### move

A kernel adding a vec3 to another for the rows with two tags: integration, animation, any per-row update.

- **N:** 250K matched rows; usually 1K–1M.
- **Best:** 36 bytes per N at the copy bandwidth of one thread, the fastest it measured. Each row reads 12 bytes of velocity and reads and writes 12 bytes of position.

### churn

A main-thread system despawning a tenth of its rows and spawning as many: projectiles, particles, pooled UI.

- **N:** 1M rows visited; usually 1K–100K.
- **Best:** 29 bytes per N at the copy bandwidth of one thread, the fastest it measured. Each row reads 16 bytes; each tenth swaps the last row into its hole, 88 bytes, and spawns one of 44.

### retag

A main-thread system adding a tag to a tenth of its rows and removing it from another tenth: state flags such as selected or visible that move entities between archetypes.

- **N:** 1M rows visited; usually 1K–100K.
- **Best:** 39 bytes per N at the copy bandwidth of one thread, the fastest it measured. Each row reads 4 bytes; each fifth moves, copying its 44 bytes and swapping the last row into its hole.

### sparse changed

A kernel filtered on `changed` after 1% of rows changed, scattered: reacting to edits, such as recomputing bounds of what moved.

- **N:** 1M rows in the archetype; usually 10K–1M.
- **Best:** 8.24 bytes per N at the copy bandwidth of one thread, the fastest it measured. Every chunk has a change, so each row's 8-byte tick is read; the changed 1% read 12 bytes and write 12.

### sparse changed clustered

The same with the 1% in one contiguous run of rows, as edits to recently spawned entities are.

- **N:** 1M rows in the archetype; usually 10K–1M.
- **Best:** 0.33 bytes per N at the copy bandwidth of one thread, the fastest it measured. Chunk ticks are scanned; the changed 1% read their 8-byte ticks and 24 bytes of values.

### follow

A kernel looking up another entity per row and reading its position: steering toward targets, constraints, attachments.

- **N:** 1M rows; usually 1K–100K.
- **Best:** 52 bytes per N at the copy bandwidth of one thread, the fastest it measured. Each row reads 12 bytes of position and an 8-byte target, the target's 8-byte location and 12-byte position, and writes 12.

### emit

A kernel issuing an add for a tenth of its rows: hits, events or state changes found by a parallel pass.

- **N:** 1M rows; usually 1K–100K.
- **Best:** 34 bytes per N at the copy bandwidth of one thread, the fastest it measured. Each row reads 16 bytes; each tenth moves to a new archetype, about 180 bytes.

### reduce

A kernel folding every row into a sum and a maximum: totals, bounds, counts.

- **N:** 1M rows; usually 1K–1M.
- **Best:** 4 bytes per N at the copy bandwidth of one thread, the fastest it measured. Each row reads its 4-byte value.

### chain

Six dependent kernels over the same rows, each reading what the one before wrote: a pipeline of per-row steps.

- **N:** 6M row passes; usually 6K–6M.
- **Best:** 4 bytes per N at the copy bandwidth of one thread, the fastest it measured. Fused into one pass, each row reads and writes its 12-byte velocity once for all six.

### up depth 10

A kernel with `up` computing every row from its parent, over 100K chains of 10: transforms, inherited visibility or style, recomputed in full.

- **N:** 1M rows; usually 1K–100K.
- **Best:** 28 bytes per N at the copy bandwidth of one thread, the fastest it measured. Each row reads its 8-byte value, its parent's 8-byte result and 4-byte row, and writes its 8-byte result.

### up depth 1000

A kernel with `up` computing every row from its parent, over 1K chains of 1,000: transforms, inherited visibility or style, recomputed in full.

- **N:** 1M rows; usually 1K–100K.
- **Best:** 28 bytes per N at the copy bandwidth of one thread, the fastest it measured. Each row reads its 8-byte value, its parent's 8-byte result and 4-byte row, and writes its 8-byte result.

### up one root changed

A filtered kernel with `up` after one root's value changed: moving one object in a scene graph.

- **N:** 1M rows; usually 1K–100K.
- **Best:** 0.00781 bytes per N at the copy bandwidth of one thread, the fastest it measured. Chunk ticks are scanned; the 10 rows of the changed chain run.

### up after a spawn

A kernel with `up` computing every row, after a spawn into its tree: a node added to a scene graph each frame.

- **N:** 1M rows; usually 1K–100K.
- **Best:** 28 bytes per N at the copy bandwidth of one thread, the fastest it measured. The run itself, with the order kept current at O(1) for the spawn.

### up filtered after churn

A filtered kernel with `up` after one root changed and 100 leaves were despawned and 100 spawned in the tree's archetype: a scene graph with objects coming and going.

- **N:** 1M rows; usually 1K–100K.
- **Best:** 0.0137 bytes per N at the copy bandwidth of one thread, the fastest it measured. Chunk ticks are scanned; the changed chain and the 200 leaves run; the order is patched for 200 rows.

### up filtered after tagged churn

A filtered kernel with `up` after one root changed and 100 leaves were despawned and 100 spawned, the leaves in an archetype of their own: a scene graph with short-lived children of their own kind, such as effects.

- **N:** 1M rows; usually 1K–100K.
- **Best:** 0.0137 bytes per N at the copy bandwidth of one thread, the fastest it measured. Chunk ticks are scanned; the changed chain and the 200 leaves run; the order is patched for 200 rows.

### up filtered after a reparent

A filtered kernel with `up` after a subtree of 9 rows moved to another parent: dragging an object to a new group.

- **N:** 1M rows; usually 1K–100K.
- **Best:** 0.00781 bytes per N at the copy bandwidth of one thread, the fastest it measured. Chunk ticks are scanned; the 9 moved rows are renumbered and run.

### up load

Spawning a forest of 100K chains of 10 and running a kernel with `up` over it once: loading a scene.

- **N:** 1M spawns; usually 1K–100K.
- **Best:** 68 bytes per N at the copy bandwidth of one thread, the fastest it measured. Each entity writes 24 bytes of values, its entity and its location, then runs once.

### up small tree in a big world

A kernel with `up` over a tree of 1K rows after a spawn into it, in a world of 1M other entities: a UI or a rig beside a large simulation.

- **N:** 1K tree rows; usually 100–10K.
- **Best:** 28 bytes per N at the copy bandwidth of one thread, the fastest it measured. The run over the tree, with the order kept current at O(1) for the spawn.

### main thread

Fifty main-thread systems each reading every row of 1K: many small app systems.

- **N:** 50K row reads; usually 1K–100K.
- **Best:** 12 bytes per N at the copy bandwidth of one thread, the fastest it measured. Each row read loads its 12-byte position.
